## 0. 采纳纪律（Ivan 2026-07-31）

> **能用原生 Shortcuts 做的，一定用原生。** 第三方依赖只在原生确实做不到时才引入。

按这条重筛之后，本项目**真正需要它的只有一个动作**（`Is Silent Mode On`），
另有一个待验证（语言代码，先查原生）。其余全部砍掉 —— 详见 §4 的"别用"清单。

每引入一个第三方动作，就多一份"某次 iOS 更新后静默失效"的风险（见 §1）。
收益不明确的一律不引入。

---

## 1. 为什么它仍然值得装

这个 App 推翻了本项目设计里**唯一一条硬约束**。

`ATOMIC-RULES.md` §2.2 原文（现已作废）:

> 不可观测字段的硬限制: 任何记忆（本地 la 或云端回传）只能记住"我做了什么"，
> 永远不知道"你之后改了什么"。搬到云端也解决不了，除非 iOS 给读接口。

这条约束是针对 `silent` 写的，它决定了 `silent` 只能用 `if_changed`（比本地记忆）而不能用
`if_differs`（比实测态）。**`Is Silent Mode On` 就是那个"除非"。**

## 2. ⚠️ 装它之前必须知道的三件事

| # | 事项 | 后果 |
|---|---|---|
| 1 | 商店页写"装完/更新完必须重启设备"，**但 Ivan 2026-07-31 实测未重启也正常** | 说明这条与设备/iOS 版本有关，不是必然。**兜底纪律照留**（§6）—— 一次没撞上证明不了永不发生，而它的失效形态是静默的 |
| 2 | 需要 **iOS 26+** | 旧系统装不了 |
| 3 | **Apple Watch / HomePod 上跑不了** | 这些设备上的自动化不能依赖本 App 的动作 |

第 1 条最阴险: 它不是"报错"，是"动作凭空消失"，而消失的表现是快捷指令**静默失败**。
凡是用了本 App 动作的指令，都应该在尾部有一条"没拿到值就告警"的兜底。

## 3. 值得用的（只有这些）

### 3.1 `Is Silent Mode On` —— 唯一原生做不到、又确实需要的

**实测结论**: 配合隔离带（下方写法）输出稳定（Ivan 2026-07-31）。

**它到底解锁了什么 —— 别搞错**:

| 说法 | 对不对 |
|---|---|
| `silent` 的可选判据扩到全三档 | ✅ 机制上成立 |
| 所以 `silent` **该**改用 `if_differs` | ❌ **不对**。判据是策略选择，不是能力问题。`if_differs` 会在你半夜手动解除静音后又给你静音回去 —— 和 focus 夜间段选 `if_changed` 是同一个理由 |
| 真正的价值 | ⭐ **回传实测态**。服务端第一次能知道"手机现在到底静没静音"，这是漂移检测/自愈的输入。此前 `silent` 是三个字段里唯一的盲区 |
| 次要价值 | `silent` 现在也能挂守卫了（如"只有当前确实静音才解除"）；解除侧可用观测替代 `la` |

（本文档初版把它写成"可以上 `if_differs`"，暗示应该改，是夸大了，已改正。）

**⚠️ 输出是本地化的**（Ivan 实测）: 中文系统返回 `是`/`否`，英文返回 `Yes`/`No`。

**但这不需要任何新机制。** 本项目早有成规 —— `PHONE.md` 铁则7 / `CHANNELS.md` §6.4:

> iOS 自产布尔的**呈现方式随系统语言和 iOS 版本漂移，不是契约**。拿它去比对必然失败。
> 手机端必须建一层【语言无关隔离带】: `If (布尔) is True → Text: true /
> Otherwise → Text: false`，把系统布尔翻成死文本再参与比较。

所以照抄 `Device Is Locked`（§3 G17a）那套写法即可:

```
A1  Is Silent Mode On                      ← Actions
A2  If (A1) is True  → Text: true
    Otherwise        → Text: false          ← 隔离带，从此与语言无关
A3  用 A2 的结果参与比较 / 回传
```

> ❌ **不要**在服务端加 `silent_state` 的 token→本机名解析表。
> 那等于拿"呈现"当契约，正是铁则7 禁止的事。
> （本文档 2026-07-29 初版曾把这条列为"二选一"之一，是错的，已改正。）

### 3.2 语言代码自报（**先查原生**） —— 根除 2026-07-27 那类事故

**结论: 必须用 Actions**（Ivan 2026-07-31 确认，此前也考虑过）——
原生 `Get Device Details` **没有**语言字段，本项目已在用的只是它的 `Device Is Locked`
（PHONE §3 G17a）。所以这是第二个通过 §0 纪律的动作。

用 `Get User Details` → Language Code，在 SyncAll 组 URL 时自己拼上 `&locales=<码>`。

> **服务端已加兜底**（2026-07-31）: 缺 `locales` 时不再整表不下发，而是**降级为全语言表**
> + 一条 `locales_fallback` 告警。原先 fail-closed 的后果是 `match` 全空 → `in` 永远拦截
> → **focus 整个报废**；瘫痪比"少保护"糟得多。
> 兜底只保证不瘫痪，**候选顺序不再以系统语言优先**（Set Focus 要多试几个名字，每次带 Wait
> 会慢一点），所以语言自报仍然是正解，兜底是安全网不是替代品。

**影响**: `?locales=` 不再需要人手写进 URL。那次事故的形状是——URL 里混进不可见字符 →
`locales` 收不到 → `resolve.current_focus` 整表不下发 → 所有守卫 `match` 为空 →
`in` 永远拦截 → 专注整天不解除，**而且 trace 里一个字都没有**。

手机自报之后，这条路径从"可能出错"变成"不可能出错"——参数不是人写的了。

（服务端的空展开告警仍然留着，那是第二道防线。）

### 3.3 ~~`Global Variable` 替代 la 文件~~ —— 已砍

现状: `la_focus.txt` / `la_silent.txt` / `la_volume.txt` 存在 iCloud Drive 的
Shortcuts 文件夹里（Ivan 截图确认）。

**风险**: iCloud 同步有延迟，网络不好或多设备时可能**读到旧值**。而 la 的全部意义就是
"我上次交代了什么"—— 读到旧值等于记忆错乱，比没有记忆更糟。

`Global Variable` 是 App 级持久变量，本地读写、不过 iCloud。更快也更可靠。

**结论: 不做。** iCloud 延迟对**单设备**基本是理论风险，而现有文件方案已经在稳定运行。
为一个没观测到的风险引入第三方依赖，不划算。
真出现"读到旧值"的实锤（表现: la 与实际态对不上且能复现）再回来看这条。

## 4. 别用（原生已有 / 收益不明确）

初版曾把下面这些列为"能用的"，按 §0 纪律重筛后全部剔除。留在这里是**防止将来有人重新提议**。

| 动作 | 为什么不用 |
|---|---|
| `Is Device Locked` | **原生 `Get Device Details` 已有**，PHONE §3 G17a 正在用 |
| `Show Notification` | 原生已有同名动作 |
| `Get Contents of URL (Extended)` | 原生够用；没观测到超时控制不足的实锤 |
| `Get Values Using JSONPath` | 原生 Get Dictionary Value 够用，只是啰嗦一点 —— 不值一个依赖 |
| `Wait Milliseconds` | ApplyFocus 的等待现在是秒级，够用 |
| `Counter` | 重试计数用现有的文件/变量就行 |
| `Global Variable` | 见 §3.3，单设备下是理论风险 |
| ~~`Get High-Resolution Timestamp`~~ | ⭐ **2026-07-31 改判为采纳** —— 当时理由是"延迟实验没在做"，现在有了 Shortcut Timed Out 的实案，原生秒级精度量不出哪一步慢。见 `PHONE-TELEMETRY.md` §4 |
| `Sign JSON Web Token` | 安全升级不是当前痛点；key 泄露最坏是"能写事实"，可换 key |
| `Transform Text with JavaScript` | **主动拒绝**: 逻辑下沉到手机就违背"规则的唯一真相在服务端" |

**待观察（现在别做，出现实锤再回来）**

- `Is Online` / `Is Host Reachable` / `Ping` —— 回传前判网。后台预算只有 40–80 秒且掐尾部，
  无网时白等一次超时确实亏。但这只在 **P-观测上线后**才有意义，且要先测出"无网重试真的
  吃掉了预算"才值得引入。

## 5. 实测台账（2026-07-29 / 07-31）

| # | 结论 | 影响 |
|---|---|---|
| 1 | 原生 `Get Device Details` **没有**语言字段 | 语言自报必须用 Actions 的 `Get User Details` → Language Code |
| 2 | `Is Silent Mode On` + 语言无关隔离带 **输出稳定** | `silent` 成为可观测字段；主要价值是回传实测态（见 §3.1） |

| 4 | `Is Silent Mode On` 返回值随系统语言变（`是`/`Yes`） | 走铁则7 的隔离带，**不加** `silent_state` 解析表 |

## 6. 采纳清单（最终）

**采纳三个动作**

| 动作 | 用途 | 手机端改动 |
|---|---|---|
| `Get User Details` → Language Code | SyncAll 组 URL 时自拼 `&locales=<码>` | 一处（组 URL 那步） |
| `Is Silent Mode On` + 隔离带 | 回传 `silent` 实测态 | 回传阶段做，现在不动 |
| `Get High-Resolution Timestamp` | 埋点的毫秒时间戳（原生只有秒级） | 见 `PHONE-TELEMETRY.md` |

**顺手一起做的建议**: 语言自报这处改动，和这轮要建的 `|SYNCALL|` 通知自动化
一起做完 —— 反正都要进快捷指令编辑器，一次搞定省得来回。

---

## 7. 一条纪律

本 App 是**第三方依赖**。凡是用了它的动作，必须满足:

> 拿不到值时能**看得出来**，而不是静默走默认分支。

理由见 §1 第 1 条: 它的失效形态是"动作消失"而不是"动作报错"。
一次 iOS 更新 + 忘记重启，就能让整条链路无声地退回到某个错误的默认值。
