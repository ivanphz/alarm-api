# 08-LESSONS — 踩坑总账

> 每条都真实踩过。**代码里已经修好的，这里只记「为什么会那样」** —— 防止将来有人
> （包括 AI）觉得某条限制多余而把它拆掉。
>
> 这份文档取代了原来 31 份归档。**删掉的东西在 git history 里**，需要考古用
> `git log --diff-filter=D --name-only` 找。

## 0. 一条元教训

**这个项目的失败几乎全是「静默失效」**：不报错、不崩溃，就是某件事悄悄没发生。
所以所有设计都偏向 fail-loud：宁可当场炸，不要安静地错。

看到「静默」两个字就要警觉 —— 下面每一节几乎都有它。

# 一、iOS 快捷指令

## 1.1 布尔值不是契约

iOS 把 JSON `true` 渲染成**本地化文本**：中文「是」、英文「Yes」，历史上还出现过 `1`/`0`。

**定案**：服务端一切真值下发字符串 `"true"`/`"false"`；手机端对**自产**布尔
（如 `Device Is Locked`、`Is Silent Mode On`）必须建「语言无关隔离带」：
`If (布尔) is True → Text: true`，翻成死文本再参与比较。

有一条测试递归扫描整个信封，任何位置出现 boolean 就失败。

## 1.2 判空不能用 `has any value`

存在「0 即空」的版本怪癖，两边行为不一致（音量 0 被当成空）。

**定案（无豁免）**：标记法 —— `Text: X（插入变量）` → `If (该文本) is X`，命中即空。
全手册 `has any value` 零残留。

## 1.3 同一个变量名一个指令里只 Set 一次

**事故**：`Get Value for mode in FocusDict → Set variable FocusDict`
把字典自己覆盖成字符串，后续取值全空，表现为「连 07:44 都关不掉」。

## 1.4 Find Alarms 只按名称 → 时间必须编进 label

快捷指令**没有「改现有闹钟时间」的动作**。同名闹钟找到后只能 Turn On，时间永不更新
（静默失效）。

**定案**：label 尾部编入时间（`GateDyn-Event-0810`）。改时间 → label 变 → 旧的被 sweep
关掉、新的重建。**时间由网关拼**，业务侧 uid 永不含时间。

## 1.5 Create Alarm 建的闹钟指定不了铃声

由此分出两类：绝不能漏响的 → 预建 `GateFix-*`；时间会变的 → 动态 `GateDyn-*`。

## 1.6 Set Focus 吃变量，但必须是本机语言显示名

**曾误判为「不吃变量」。** 实际吃文本变量，但喂进去的必须是本机名（随系统语言变）。

三重保险：① URL 带 `&locales=`；② 服务端下发 token→**候选名数组**，手机逐个试开；
③ iOS 改译名只需服务端加一行。

三个附带铁则：
- **候选名数组绝不能过 `Text` 动作** —— 会变成 `"A, B"` 死文本，必失效
- **「先关当前专注」只做一次、在候选循环外** —— 塞进循环会偶尔漏关
- **当前专注已在候选里则跳过清场** —— 无脑 Off→On 会让绑该专注的其他自动化被误触发两次

## 1.7 focus 的 la 必须存签名 `preset|action`

**事故**：跨 preset 同 action 切换（勿扰 on → 睡眠 on）被判「没变」跳过，新 preset 永不生效。
根因是 la 只存了 action。

preset 用 token，所以签名跨语言稳定 —— 存显示名的话换语言就天天误判。

## 1.8 guards 必须在字段级

**事故**：服务端把 guards 塞进 `value` 内部，focus 守卫读 `.value.guards` 多一层 → **永久失效**。

**定案**：`extractGuards` 提到 `fields.<x>.guards`，三字段路径统一。

## 1.9 集合守卫用 `in`/`not_in`，否决 `contains`

bundle id 前缀高度重合（`com.app.a` ⊂ `com.app.about`），子串匹配会误命中。
服务端校验 value 必须是数组，否则丢弃 + 告警（**不静默放行坏守卫**）。

> 同一个坑的另一面：门铃关键词也用 `contains`，所以必须带分隔符 `|SYNCALL|`。

## 1.10 CheckGuards 必须短路

Repeat 里只 Set 变量不跳出 → 空跑拖慢 + 变量污染。命中即 `Stop and Output: SKIP`。

## 1.11 自动化「运行前询问」必须关

否则后台完全不触发。上线冒烟必查。

## 1.12 后台 ≠ 前台

`Show alert` 在后台不一定弹，前台测出来的「都正常」不代表后台正常。
调试用 `Append to Note/File`（变量用 `[ ]` 包住便于看出空值）。

**另一坑**：append 里直接放非文本变量（如 Current Focus 对象）会存成 `Attachment.txt`
—— 先过一道 `Text`。

## 1.13 快捷指令 JSON 导出不完整

从导出审 ApplyFocus，OFF 分支的 `Set Focus` 缺 `Enabled` 字段，差点误判成生产 bug；
**UI 里明确是 Turn Off，只是导出没序列化该标志**。

**定案**：导出不能当唯一真相源，以 UI 实际显示为准。

## 1.14 la 每字段独立文件

共用一个文件会互相覆盖。
**路径陷阱**：File 动作的灰色预设根目录若已是 Shortcuts，路径**只填文件名**，
再写 `Shortcuts/` 前缀会套娃。

## 1.15 ⛔ `Get Dictionary from Input` 喂数组会静默清空

**这条是「传言被引用五个版本后才被实测证伪」的典型。**

传言：「结构穿过 `Run Shortcut` 边界会被降级成纯文本」—— v4.1 一次评审提出，
被引用了五个版本，**从未验证**。2026-07-26 实测：

| 传的东西 | 不洗 | 洗（`Get Dictionary from Input`）|
|---|---|---|
| 手工字典 | ✅ | ✅ |
| URL 信封 | ✅ 读出 `version: 2` | ✅ |
| **数组** `[1,2,3]` | ✅ **Count=3 完好** | ⛔ **Count=0，静默清空** |

**结构穿边界没问题，危险的是「洗」这个动作本身。**

两条硬规矩：

1. **绝不对数组做 `Get Dictionary from Input`** —— 不报错、不提示，直接返回空。
   具体后果：若 CheckGuards 直接收 `guards` 数组再洗，就是 `Count=0` →
   **所有守卫被当成 0 条而全部放行**。
2. **别让裸数组过边界 —— 包进字典再传。** 不是因为数组过不去（过得去），
   而是**接收方一旦按习惯洗一下就全毁了**。包成字典后，
   洗字典（安全）→ 内部掏数组（安全），**不存在「记得别洗」这种负向规矩**。

> 设计原则：**能靠结构消灭的负向规矩，就别写进文档指望人记住。**

## 1.16 别拿提醒事项的心智套闹钟

提醒事项能 `Set Detail` **就地改到期日** → 「改期即改铃、身份不变」。
闹钟**做不到**，只能关旧建新（§1.4）。

**两者的对账模型因此根本不同，不要互相借鉴实现。**

## 1.17 单槽 · 串行 · 忙丢

运行期间到达的触发**全部丢失**，不排队不补跑（实测长任务运行期 30 响仅首响生效）。

**推论**：所有边界必须幂等；这也是 `pulse`「不重放」的独立佐证。

---

## 1.18 「文本化三明治」：比较操作数一律先过 `Text`，判空用原始值

铁则1 的机械化版本。病灶是**混型比较行为不定型** ——
`media_volume` 是数字，哨兵 `none` 是文本，两者比较结果不可预测。

**定案**：`If` 的输入与条件对象**必须全是文本**（各自先过一次 `Text`）；
判空则用**原始变量**走标记法。两句话，无个案豁免。

## 1.19 命名纪律：八名封顶，一次性值用魔法变量

一个指令里命名变量**不超过 8 个**；只用一次的中间值不要 `Set Variable`，
直接引用上一步输出（魔法变量）；**复取宁可重 Get，也不要为了省一次 Get 而多一个名字。**

起因：一次二审发现命名过密，读的人分不清哪些是状态、哪些是临时值 ——
而变量名一多，铁则4（别用不同类型覆盖同名变量）就更容易被违反。

# 二、Worker 侧

## 2.1 iOS 定时自动化会晚触发 → 刺客必须自报计划时间

**事故**：不带 `now` 时 07:44 的解除偶发失效。point 匹配容差 ±3 分钟，而 iOS 后台触发
常晚几分钟 → 没命中 → 字段缺席 → 下游全不跑，**看起来像「守卫坏了」，其实是上游没匹配**。

**定案**：每个刺客把自己的**计划时间**传进来（`?now=HH:MM`）。

> 附带教训：测试时写死的 `?now=13:29` 这类残留**上线前必清**。

## 2.2 ICS 裸 UTC 差 8 小时

旧 parseICS 只正则抠 `T(HHMM)`，没看 `Z`/`TZID` —— `…T093000Z`（对应上海 17:30）
被当成上海 09:30。

**定案**：捕获 `startTZ`，`toShanghaiWall()` 统一换算（Z/±HH:MM 精确、IANA 名走 `Intl` 含 DST）。

## 2.3 ICS 反转义不完整（潜伏最久）

上帝模式 JSON 在 v1/v2 **双双**解析失败，一度误判为智能标点污染。
真凶：RFC 5545 要求逗号转义为 `\,`、分号为 `\;`，解析器只还原了 `\n`，
**残留反斜杠让 `JSON.parse` 失败**。

**教训**：两个版本同时出错 = 大概率是共用的底层组件，不是迁移 bug。

## 2.4 替换代码时，它携带的容错语义也是接口的一部分

接入 `workdays-core` 时，原实现的「拉不到 → 空数据 → 周末推演」降级被顺手删了，
core 一抛错整个请求就崩。

## 2.5 最外层兜底返回 200 而不是 500

任何未接住的异常 → **HTTP 200 + 格式合法的降级响应**（fields 空 → 手机空转不误动）。

**为什么不是 500**：手机端 fetch 拿到 500 会让整条同步失效；200 + 空状态让手机
「安全地什么都不做」。

## 2.6 跨模块匹配必须用稳定标识，不能用展示名

曾用假期**中文名**匹配，但范围名带装饰（`"暑假(每年固定)"`）≠ 键。

## 2.7 交付含双轨的包必须做「从入口全图解析」校验

否则会出现某个文件语法就过不了、但没人发现的情况。

# 三、本项目特有的设计事故

## 3.1 「同值 = 没变化」是电平假设，对脉冲不成立

**事故（长假）**：每晚都是 `sleep|on`，相邻同值被归一化合并 → 只有第一晚有边界，
之后**夜夜查无此字段**。

这个假设当时硬编码在 kernel **三处**（`normalize` / `samplePoint` / `clampToRange` 的跨界锚定），
改一处两处都不够。

**定案**：边界带 `shape`，pulse 永不合并。

## 3.2 守卫 SKIP 不落账 → la 冻结 → 死锁

**事故（出差）**：出差事件占了午间区带 → 无午间两键 → 晨间守卫拦下不落账 →
`la` 冻在 `sleep|on` → 夜间被判「没变化」跳过 → **连着几晚不进睡眠，全程无报错**。

平时是 13:29 那条无守卫的边界在**无意中当死锁解除器**，出差恰好把它抽走。

**现状**：全 pulse + `always` 缓解了大部分；根治要等回传自愈（比实测态而不是比 la）。

## 3.3 fail-closed 用错地方会变成瘫痪

**事故**：URL 混进不可见字符 → `?locales=` 收不到 → resolve 整表不下发 →
守卫 `match` 全空 → `in` **永远拦截** → 专注整天不解除，**trace 里一个字都没有**。

**定案**：改为**降级全语言兜底 + 响亮告警**。瘫痪比「少保护」糟得多。

> 一般原则：fail-closed 适合「做错事的代价 > 不做事的代价」的场合。
> 守卫展开不属于这类 —— 它不做事的代价是整个功能失效。

## 3.4 为不存在的问题发明机制

**事故**：晨间解除用「有界电平」是为了漏发兜底，但常规日子**根本没有后续调用**能补
（下一个刺客是 point 模式，看不见那个边界）。于是窗口什么都没提供，却制造出一个
落不到刺客上的撤销边界；我又为了安置它发明了「吸附到下一个刺客」，结果周末吸到了 12:15
—— 上午的解除和中午没有任何语义关系。

**定案**：删掉窗口，解除直接用 pulse。**先问「这个机制解决的问题真的存在吗」。**

## 3.5 用外部资料覆盖实机台账

**事故**：网络搜索说「iOS 没有通知触发自动化」，据此写了一整套绕行设计。
而两周前的实测台账里明明白白记着通知触发可用且已在用。

**定案**：手机能力的问题**先查 05-FACTS，不查外部文档**。台账没有的才实测，实测完写回去。

## 3.6 已有实测结论的事，不许让人重测

2026-07-17 实案：多语言 `Set Focus` 的方案早在 DEVLOG 里有实测定论，
我却在方案文档里标了「待手机实测」—— **这是倒退**，等于让 Ivan 把已经做过的实验再做一遍。

**定案：动手机方案前先查 [05-FACTS](05-FACTS.md)。** 台账里有的，直接用；
台账里没有的，才安排实测；实测完**当场写回台账**。

> 同一个错误在 2026-07-31 又犯了一次（用网络搜索的结论覆盖实机台账，见 §3.5）。
> **两次都是「手上有答案却去别处找」。**

## 3.7 改代码不改文档

加了日型轴、改了时刻、改了形状，而手册里还写着旧时刻、旧机制。

**定案**：`test/docs.test.js` 把「文档说的 = 代码做的」变成会红的测试
（刺客清单、已退役时刻、字段覆盖）。**光靠自觉不行。**

# 四、几条被实测推翻的判断（留着防止重犯）

| 曾经认为 | 实际 | 怎么发现的 |
|---|---|---|
| Turn Focus 必须先 `Get Current Focus` priming | 不需要。当年「复杂的行、简单的不行」是**变量自我覆盖**（1.3），归因错了 | 2026-07-17 实测复核 |
| Set Focus 不吃变量 | 吃文本变量（须本机名） | v1 文档实证 |
| iOS 没有「通知触发自动化」 | 有，且早就在用 | 查台账（见 3.5） |
| 埋点的大头是第三方 App Intent 的 IPC | 反了 —— 写入占 79%，IPC 只占 21% | 加基线对照实测 |
| Actions app 装完必须重启 | 商店页这么写，但实测未重启也正常 | 装完先不重启试 |
| silent 永远不可观测 | Actions 的 `Is Silent Mode On` 破了这条 | Ivan 发现该 App |

**共同点**：五条里有四条是「凭推理下的结论」，被一次实测推翻。
**能测就测，别推理。**
