# 02-RULES — 规则怎么写、怎么改

> 想改「几点做什么」，只看这一篇。概念不懂先看 [01-CONCEPTS](01-CONCEPTS.md)。

---

## 0. 三十秒心智模型

```
人生事实（上班/放假/年假/长假/出差/会议/暑假/上帝模式）
      ↓ 事实插件翻译成【日型四轴】，全系统共用，永不重复实现
决策规则（RULES：什么时候、什么条件、做什么）
      ↓ 纯配置
字段（focus / silent / media_volume）
      ↓
手机执行器
```

**改动永远先问自己：我改的是「事实」（世界是什么样）、「决策」（该做什么），
还是「效果」（具体设成什么）？** 三层对应三种改法，成本递减。

### 0.1 变更配方表

| 想改什么 | 动哪一层 | 难度 |
|---|---|---|
| 时刻常量（07:44 → 07:50） | config 的 `DND_TIMES` + **手机上同步改刺客** | ⭐ |
| 标题关键词（加「调休」） | `KEYWORDS` | ⭐ |
| 某个边界的值/形状/判据/守卫 | `RULES` 里那一行 | ⭐ |
| 某个边界的日型条件 | 同上，改 `when` | ⭐⭐ |
| **新的人生事实**（如「旅行中」） | `plugins/day-type.js` 加一根轴 + `kernel/rules.js` 的 `WHEN_AXES` 登记 | ⭐⭐⭐ |
| 新字段（如铃声音量） | config 加字段 + **手机端复制一份 Apply 指令** | ⭐⭐⭐ |
| 改信封/端点/采样 | `edge/` —— 动手机契约，要灰度 | ⭐⭐⭐⭐ |
| **想动 `src/kernel/`** | ⛔ **先停** —— 见 §6.2 第 2 条 | |

### 0.2 服务端落点速查（要写代码时）

§0.1 是「改配置」，这张是「写代码」——**别放错层**：

| 要加什么 | 放哪 | ⛔ 禁止放哪 |
|---|---|---|
| 外部数据拉取 / 解析 | `edge/sources.js` | 插件（纯度红线：禁 I/O） |
| 时区换算 / 窗口 / 标签构造 | `edge/assemble.js` + `domain/alarm-labels.js` | 插件 |
| 新决策规则 | `config` 的 `RULES`（优先）或 `src/plugins/新文件` | `src/kernel/` |
| 新事实（日型的新轴等） | `src/plugins/新文件` 或扩展 `presence` / `day-type` | `edge/` |
| diff / 漂移 / 推送 | `edge/reconcile.js`（待建）+ `edge/push.js` ✅ | 插件 |
| 新配置项 | `config.default.js`（默认值）+ `config.user.js`（你的领地） | 硬编码进 `src/` |
| 信封新字段 | `edge/assemble.js` 组装 | `src/kernel/` |

## 1. 改之前先知道去哪改

| 想改 | 去哪 |
|---|---|
| 时刻 / 参数的**值** | `src/config.user.js` 覆盖（`config.default.js` 会被新版覆盖，改了会丢） |
| 规则的**结构**（加条件、改形状） | `src/config.default.js` 的 `V2.FIELDS.<字段>.RULES` |
| 看规则最终长什么样 | 部署后访问 `/v2/schema` |
| 看某天几点会发生什么 | `/v2/timeline?date=2026-08-05&debug=1` |
| 看哪些边界需要门铃 | `/sweep/plan?hours=48&key=...` |

## 2. 当前时刻表

### 2.1 常量（`config.default.js` 顶部）

```js
DND_TIMES = {
  NIGHT_ON_WORKDAY_EVE: "20:55",   // 在家 + 明天上班
  NIGHT_ON_REST_EVE:    "22:25",   // 在家 + 明天休息 / 或今晚不在家
  MORNING_OFF_WORKDAY:  "07:44",   // 工作日晨间解除的【下限 + 兜底】
  MORNING_OFF_WEEKEND:  "09:30",   // 周末晨间解除
  NOON_ON:  "12:15",  NOON_OFF: "13:29",
}
WAKE_RELEASE_OFFSET = 20     // 起床闹钟响完多久解除
MORNING_LATE_EDGE   = "08:00"  // 与 ZONES.MORNING.end 同源：再晚归人管
```

⚠️ `DND.WHITELIST` 从 `DND_TIMES` **自动派生**。在 `config.user.js` 里改了时刻，
必须**一并覆盖 WHITELIST**（数组是整段替换，不会自动合并）。

### 2.2 各场景实际时刻

| 场景 | 晨间解除 | 夜间进入 | 门铃 |
|---|---|---|---|
| 普通工作日 | **07:44** | 20:55 | ❌ |
| 周五（明天休） | 07:44 | 22:25 | ❌ |
| 普通周末 | **09:30** | 22:25 | ❌ |
| 长假中段/尾巴 | **不解除**（绝不吵醒） | 22:25 | ❌ |
| 出差·事件带时间 | **闹钟+20**（如 08:30） | 22:25 | ✅ |
| 出差·全天事件 | 07:44（无闹钟可锚 → 兜底） | 22:25 | ❌ |
| 出差最后一天（下午结束） | 闹钟+20 | **20:55**（晚上已到家） | ✅ |

> 晨间解除锚定「当天最晚**起床**闹钟 + 20 分钟，不早于 07:44」。
> 所以平时闹钟 06:29 也不会提前解除 —— 吸附到 07:44，落在刺客上，零门铃。

## 3. 一条规则长什么样

```js
"20:55": {
  when:  { night: ["home"], eve: ["workday"] },   // 条件：四轴取交集
  value: "on",                                     // 做什么
  shape: "pulse",                                  // 主张多久
  apply: "if_changed",                             // 凭什么动手
  guard: "none",                                   // 什么情况让路
  note:  "明天上班 → 今晚提前进睡眠",
}
```

| 键 | 可选值 | 缺省 |
|---|---|---|
| `when` | `{ morning/noon/eve/night: [...] }` | 无条件 = 总是 |
| `value` | 字面量；`null` = 释放主张 | 省略 = 继承订阅（现已不用） |
| `preset` | focus 换挡（`do_not_disturb` 等） | 字段的 `PRESET` |
| `shape` | `"level"` / `"pulse"` | 字段的 `SHAPE` |
| `until` | `"HH:MM"` 或 `{ offset: N }`（仅 level） | 无 |
| `apply` | `always` / `if_changed` / `if_differs` | 字段的 `APPLY` |
| `guard` | `"none"` / `"sleep"` / 数组 | 无守卫 |
| `at` | 时刻表达式（键为 `"@具名"` 时用） | 键本身就是时刻 |

**一格多条变体**写成数组，每条都必须有 `when` 且互斥：

```js
"22:25": [
  { when: { night:["home"], eve:["rest"] }, value:"on", shape:"pulse" },
  { when: { night:["away"] },               value:"on", shape:"pulse" },
]
```

## 4. 三个字段共用一份骨架

`focus` / `silent` / `media_volume` 的**时刻和日型条件完全一样**，只有值和判据不同。
所以抽成了 `quietShape()`（`config.default.js` 顶部）：

```js
focus: {
  RULES: {
    ...quietShape({
      onValue: "on", offValue: "off",
      onExtra:  { guard: "none"  },   // 进入侧：手动开着专注就让路
      offExtra: { guard: "sleep" },   // 解除侧：只解除睡眠
    }),
    // 午休是 focus 独有的
    "12:15": { when:{noon:["work"]}, value:"on", shape:"pulse",
               apply:"always", preset:"do_not_disturb" },
  },
}
```

**改晨/夜时刻改一处全跟。** 有条用例锁着「三个字段解除时刻必须一致」。

## 5. 常见改动怎么做

### 5.1 改起床后多久解除

```js
// config.user.js —— 改成 10 分钟
// ⚠️ WAKE_RELEASE_OFFSET 是 config.default.js 的局部常量，用户层改不了它，
//    要覆盖就得整条规则重写。想经常调的话，把它提成 CONFIG 顶层项再说。
```

现阶段：直接改 `config.default.js` 的 `WAKE_RELEASE_OFFSET`（推代码时注意别被覆盖）。

### 5.2 加一个新时刻

1. `DND_TIMES` 加一项 → `WHITELIST` 自动包含
2. `RULES` 里写规则
3. **手机上建对应的时间自动化** —— `/v2/schema` 的 `automations` 会列出来
4. 不建 = 那一刻手机不醒 = 规则永远不生效（trace 会有 `needs_doorbell`）

### 5.3 加一个日型条件

1. `plugins/day-type.js` 产出新轴
2. `kernel/rules.js` 的 `WHEN_AXES` 白名单加轴名（不加会被当场拒绝，这是故意的）
3. 规则里用 `when` 断言

### 5.4 午休改回睡眠（而不是勿扰）

删掉 `12:15` / `13:29` 那两条的 `preset: "do_not_disturb"` 即可，回落字段的 `PRESET: "sleep"`。

### 5.5 加一个字段（如铃声音量）

`config.default.js` 里有注释掉的 `ringtone_volume` 模板。**但手机端不是零改动** ——
`ApplyVolume` 写死了字段名，要复制一份改名。只是**换**通道（媒体→铃声）才是零改动。

## 6. 编译期会拦你的错误

这些写错**当场报错**，不会静默生效：

| 错误 | 报什么 |
|---|---|
| 同一格被两种书写形式各写一份 | `规则冲突: (20:55, focus) 在 … 和 … 各写了一份` |
| 一格多变体但某条没写 `when` | `每条都必须写 when` |
| `when` 的轴名写错 | `轴 "mornin" 不存在（可用: morning/noon/eve/night）` |
| 同一天两条变体同时命中 | `日型矛盾: … 有 2 条规则同时命中` |
| `pulse` 带 `until` | `pulse 不能有 until` |
| `at.from` 引用不存在的规则 | 告警 + 说明会静默回落到哪 |

### 6.0 为什么冲突是报错而不是「优先级」

同一天、同一时刻、同一字段被两条规则命中 → **响亮报错**，不做优先级、不做后写覆盖。

> **静默择一是最难查的一类 bug。** 需要「例外」就把条件写窄
> （多加一根轴的断言），而不是靠顺序压制。

### 6.1 一个还没做但值得做的检查：空匹配探测

**不能靠静态推理判断两条 `when` 是否互斥** —— 反例就在眼前：
「上班」和「休息」看着互斥，实际**全天请假日同时为真**。引擎无从知道哪些组合不可能。

所以真正管用的是动态探测：把某条规则在**足够宽的日期窗**（如 ±400 天）上求值一遍，
**一次都没命中** → 多半是拼错了轴值或写了不可能的组合 → warn。

它比静态分析强的地方：**连拼写错误一起抓**（`morning: ["wrok"]` 静态看不出问题，
但永远不命中）。目前只做了轴名白名单校验，轴**值**还没有 —— 见 [07-ROADMAP](07-ROADMAP.md)。

## 6.2 改完的自查三条

1. `npm test` 全绿，**且新逻辑有自己的用例（含一个反例）**
2. 改动落在配置层，`src/kernel/` 的 diff 为零 —— 要动 kernel 说明抽象漏了，先想清楚
3. 新时刻已在 `DND.WHITELIST` 里（自动派生），且**手机上建了对应的时间自动化**
   —— `/v2/schema` 的 `automations` 段会列出来

> 第 2 条是最容易破的。「为了这个需求改一下 kernel」十有八九是配置层表达不了，
> 那该补的是表达能力（多一根轴、多一个 shape），不是给内核打补丁。

### 判据：政策 还是 不变量？（[09-KERNEL](09-KERNEL.md) §17.5）

新规矩落地前先归类，**混为一谈是架构腐坏的主因**：

| | **政策** | **不变量** |
|---|---|---|
| 定义 | 当下这么选，换个想法就能改 | 违反了系统就不成立 |
| 例 | 07:44 解除；长假阈值 3 天；音量归零 | 插件纯函数；单一 owner；云端不存实况 |
| 落点 | **config / 规则表** | **`src/kernel/` + 契约** |
| 判据 | 「我明天想改回来会怎样？」→ 没事 | → 别处会静默塌掉 |

> **看到某条规矩需要在两个地方同时改才生效，说明它归错类了。**

## 7. 两种书写形式

内部规范形式是「触发因为主键」，但你可以用两种糖来写，加载期自动翻译：

```js
// 字段为主键（私有时刻多时直观）
FIELDS.focus.RULES = { "20:55": {...} }

// 时刻为主键（多字段共用时刻时省事）
V2.BOUNDARIES = { "20:55": { focus: {...}, silent: {...} } }
```

**内部只存一种真相**，`/v2/schema` 能反向渲染出两种视图。

## 8. 上帝模式（应急通道）

规则算错、临时特殊安排时，在日历里直接写 JSON **接管当天**，绕过所有规则。

### 8.1 两个硬条件（缺一不可）

**① 标题命中 `KEYWORDS.GOD_MODE`** —— 判定有两种方式，**不是简单的包含**：

| 方式 | 命中 | 不命中 |
|---|---|---|
| 整个标题**恰好等于**关键字 | `上帝模式` | `今天上帝模式`（多了字就不等于） |
| 关键字被**成对括号**包住（可含其它文字） | `[上帝模式]` `【上帝模式】` `今天[上帝模式]放假` | `[上帝模式`（括号不成对） |

支持的成对括号：`[] () {} 【】 （） 「」 『』 〔〕 《》`。
标题会先归一化（全角空格→半角、去首尾空白）。

> ✅ **最稳的写法：标题直接写 `[上帝模式]`**，带括号时前后可以加说明文字。

**② 备注（DESCRIPTION）里是一段合法 JSON** —— 必须写在**备注**不是标题；备注为空则不触发。

**怎么确认真的接管了**：trace 里会有 `👑 上帝模式 …: 当天完全按手写 JSON 执行，常规规则旁路`。
**看到这行才算数**；没看到就去查条件 ①。解析失败则 trace 里是 `❌ … JSON 解析失败`，
当天回落常规规则 —— **写坏 = 当作没写过，不会半生效**。

```
标题: 上帝模式
备注: {"quiet":{"06:00":"off","21:00":"on"},
       "fixed":["GateFix-Workday-WakeUp-Vib","GateFix-Workday-WakeUp-Ring"],
       "dynamic":[{"label":"GateDyn-Custom-0930","at":"09:30"}]}
```

### 8.2 三个字段（全部可选，省略即「空」）

| 字段 | 语义 | ⚠️ |
|---|---|---|
| `quiet` | 当天安静开关时刻表 `{"HH:MM":"on"\|"off"}` | 时刻**不受白名单限制**，但落在刺客外就没人取 → 手机不会醒 |
| `fixed` | 当天要**开**的固定闹钟 label | **白名单语义**：不在列表里的一律关掉。<br>另：闹钟只在**未来 24h 窗口内**才真正开启（与平时「提前一天开好」一致） |
| `dynamic` | 当天要存在的一次性闹钟 | label 尾部必须编时间（见 [08-LESSONS](08-LESSONS.md) §1.4） |

### 8.2.1 省略 / 空值时会怎样

| 你写的 | 效果 |
|---|---|
| 省略 `fixed`（或 `[]`） | 当天**所有**固定闹钟全部关闭（白名单为空） |
| 省略 `dynamic`（或 `[]`） | 当天不新建任何一次性闹钟 |
| 省略 `quiet`（或 `{}`） | 当天 focus/silent 无任何指令（安静状态全天不动） |
| 备注写 `{}` | 三者全空 = **什么都不响、状态不动**，最安静的一天 |
| 备注 JSON 写坏 | 上帝模式**不生效**，当天回落常规规则（trace 有告警） |

### 8.3 两道输入容错（都是踩坑才加的）

- **智能标点**：iOS 键盘会把 `"` 替换成 `"`，`:` 替换成 `：` → `normalizeSmartJson` 兜住
- **ICS 转义**：RFC 5545 要求逗号转义成 `\,` → `unescapeIcsText` 单趟还原
  （这个坑潜伏最久，见 [08-LESSONS](08-LESSONS.md) §2.3）

解析失败**不静默吞错**，转 trace 告警。

### 8.4 用之前想一下

上帝模式是**逃生门不是常规手段**。反复要用同一种特殊安排，说明该加一条规则或一根日型轴。
这套将来会随可视化前端重做（[07-ROADMAP](07-ROADMAP.md) §5）。
