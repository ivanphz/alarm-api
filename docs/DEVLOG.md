# §1 iOS 快捷指令踩坑总账（血泪区，条条都真实踩过）

## 1.1 Turn Focus 无需 priming —— 当年归因错误【已更正】

- **原记载（错）**：以为 `Turn Focus On/Off` 必须先 `Get Current Focus` 才生效。
- **更正（2026-07-17 实测复核）**：**Turn Focus 本身就能生效，不需要 priming 前置。**
  当年"复杂的行、简单的不行"是**别的原因**（变量自我覆盖，见 1.2），被误归因成 priming。
- **仍然成立的**：① 守卫需要"执行时读当前专注做比对"→ 那种情况才读 `Get Current Focus`，
  是**守卫需要**，不是 Turn 需要；② iOS 同时只允许一个 focus，切换仍须先 `Turn [当前] Off`
  + `Wait 1s` 再 `Turn [目标] On`（这是 iOS 单专注限制，与 priming 无关）。

## 1.2 变量自我覆盖事故

- **现象**：重构后连 07:40 都关不掉。
- **根因**：`Get Value for mode in FocusDict → Set variable FocusDict`
  ——把字典自己覆盖成了字符串，后续取值全空。
- **定案**：**同一个变量名在一个 shortcut 里只允许被 Set 一次**；其余取值一律存新变量。
  （衍生纪律：命名八名封顶，一次性值用魔法变量，复取宁可重 Get。）

## 1.3 后台调试：Show alert 不弹，用 Append to Note

- 后台自动化里 alert 不一定弹，**前台测出来的"都正常"不代表后台正常**。
  要看真实后台行为：`Append to Note` 写固定备忘录（时间戳+变量，变量用 `[ ]` 包住便于看出空值）。
- **另一坑**：备忘录 append 里直接放非文本变量（如 Current Focus 对象）会存成
  `Attachment.txt`——先过一道 `Text` 再 append。

## 1.4 布尔值转文本是 "Yes"/"No"

- **现象**：worker 输出 JSON `true`，手机 `If Text is Yes` 居然成立。
- **根因**：iOS 对 boolean→Text 的呈现是 "Yes/No"（且历史上出现过 1/0、true/false，**不是契约**）。
- **定案**：不赌系统呈现。**比较一律先过 `Text` 动作**，服务端输出明确的字符串 token。

## 1.5 判空不能用 `has any value` —— 用"标记法"

- **现象**：音量 0 被当成空；空文本有时又不算空。
- **根因**：`has any value` 存在"0 即空"的版本怪癖，两边都有版本行为不一致。
- **定案（终案）**：**标记法** —— `Text: X（插入原始变量）` → `If (该文本) is X`（命中=空/null）。
  确定性文本相等，不赌。**全手册 `has any value` 零残留，铁律无豁免**
  ——免除未来一切个案论证。

## 1.6 Create Alarm 的两个硬约束 → 催生 Fixed/动态两类模型

- `Create Alarm` 建的闹钟**震动/铃声只能系统默认**，指定不了。
- 快捷指令**没有"改现有闹钟时间"的动作**（只能建/开/关/删）。
- 由此定案：需要自定义震动铃声或**绝不能漏响**（叫醒）→ 预建 `GateFix-*`；
  时间会变、默认铃可接受 → 动态 `GateDyn-*`。

## 1.7 Find Alarms 只按名称 → 时间必须编进 label（"改时间静默失效"大坑）

- **现象**：动态闹钟同 uid 改时间（7点→9点），手机上还是 7 点。
- **根因**：`Find Alarms where 名称 is <label>` 找到同名旧闹钟 → 只 `Turn On`，
  时间不更新（也无法更新，见 1.6）。
- **定案**：**label 尾部编入时间**。改时间 → label 变 → 旧的（不在清单）被 sweep 关掉、
  新时间重建。时间由**网关**拼（时区换算后的墙上时间），乙方 uid 永不含时间
  ——把这个正确性开关收在网关手里，乙方选错的可能性为零。
- **sweep 最终形态（v0.7 收敛）**：单一前缀 `GateDyn-` 一扫全清；`GateFix-` 天然不进 sweep。
  加新动态族不用再改手机端。

## 1.8 快捷指令 JSON 导出与 UI 脱节（差点误判生产 bug）

- **现象**：从导出审 ApplyFocus，OFF 分支的两个 `Set Focus` 缺 `Enabled` 字段，
  看起来"On/Off 不确定"，一度判为生产 bug。
- **真相**：UI 里两个动作**明确都是 Turn Off**，只是导出没序列化该标志。
- **定案**：**快捷指令 JSON 导出不完整，不能当唯一真相源；以 UI 实际显示为准。**
  手机端真相固化在 `PHONE.md`（按 UI 逐动作写），审时对照它。

## 1.9 Set Focus 吃本机语言名文本变量（曾误判为"不吃变量"）

- **我先前断言"Set Focus 开哪个专注是编辑期选死、不吃变量"是错的。**
  v1 时代文档实证：`Turn $NowText Off` / `Turn $ModeText On` —— **Set Focus 吃文本变量**。
- 但喂进去的必须是**本机语言的显示名**（`Get Current Focus` 返回的名字随系统语言变）。
- **定案（三重保险）**：① 请求带 `&locales=<系统语言>` 主路径；
  ② 云端下发 token→**候选名数组**，手机逐个试开 + `Get Current Focus` 验证，成功即短路（穷举兜底）；
  ③ iOS 改译名 → 云端加一行，手机零改。
- ⚠️ **候选名数组绝不能过 `Text` 动作**——会变成 `"A, B"` 死文本，喂 Set Focus 必失效。
- ⚠️ **"先关当前别的专注"只做一次、在候选循环外**；塞进循环内会偶尔漏关。
- ⚠️ **当前专注已在候选名单里则跳过清场**——无脑 Off→On 翻转会让绑该专注的其他 iOS
  自动化（锁屏/智能家居）被误触发两次。

## 1.10 focus 的 last_applied 必须存签名 `preset|action`

- **现象（第三方 AI 推演戳中的真 bug）**：跨 preset 同 action 切换
  （勿扰 on → 睡眠 on）被 `on_change` 判"没变"跳过，**新 preset 永不生效**。
- **根因**：`la_focus` 只存了 action。
- **定案**：Expect 升为签名 `preset|action`，落账存签名。
  **preset 用 token 故签名跨语言稳定**——否则换语言签名变，天天误判。

## 1.11 last_applied 每字段独立文件

- 拆分成独立指令后共用一个文件会互相覆盖 → 每字段一文件
  （`la_silent.json` / `la_focus.json` / `la_volume.json`）。
- ⚠️ **路径陷阱**：File 动作的灰色预设根目录若已是 Shortcuts，路径**只填文件名**，
  再写 `Shortcuts/` 前缀会套娃成 `Shortcuts/Shortcuts/…` 或权限报错。

## 1.12 CheckGuards 必须短路

- Repeat 里只 Set 变量不跳出 → 空跑拖慢 + 变量污染。
- **定案**：命中即 `Stop and Output: SKIP`。

## 1.13 guards 必须在字段级，不能塞在 value 内部

- **现象（严重）**：focus 守卫读 `.value.guards` 多一层 → **永久失效**。
- **根因**：服务端把 guards 塞进 value 内部，与 silent/volume 的字段级不一致。
- **定案（改服务端，不改手机）**：`extractGuards` 把 guards 提到**字段级**
  `fields.<x>.guards`，三字段路径统一。

## 1.14 集合守卫用 in/not_in，否决 contains

- 需求"App 是 A 或 B 才执行/不执行"。
- **否决 contains**：bundle id 前缀高度重合（`com.app.a` ⊂ `com.app.about`），
  子串匹配会误命中；且 contains 语义应是"字段含子串"而非"属于集合"。
- **定案**：`in`/`not_in` + 真数组 + 逐项精确相等。服务端校验 value 必须是数组，
  否则丢弃 + trace 告警（**不静默放行坏守卫**）。

## 1.15 自动化「运行前询问」必须关

否则后台完全不触发。上线冒烟必查。

# §2 Worker 侧踩坑

## 2.1 时刻匹配 vs iOS 自动化抖动

- **现象**：不带 `now` 参数时 07:40 的解除偶发失效。
- **根因**：point 匹配容差 ±3 分钟，iOS 定时自动化后台触发常晚几分钟 → 槽没命中 →
  focus=null，下游全不跑（**看起来像"守卫坏了"，其实是上游没匹配**）。
- **定案**：每个边界刺客把**自己的计划时间**传进来（`?now=HH:MM`），iOS 晚触发也照样命中。
- **教训**：测试时写死的 `?now=13:29` 这类残留**上线前必清**。

## 2.2 ICS 裸 UTC 差 8 小时（真 bug，已修）

- **根因**：旧 parseICS 只正则抠 `T(HHMM)`，完全没看 `Z`/`TZID`
  —— `…T093000Z`（UTC，对应上海 17:30）被当成上海 09:30。
- **定案**：parseICS 捕获 `startTZ`；`toShanghaiWall()` 统一换算
  （Z/±HH:MM 精确、IANA 名走 `Intl` 含 DST、未识别告警兜底）。

## 2.3 ICS 反转义不完整（潜伏最久的一个）

- **现象**：上帝模式 JSON 在 v1/v2 **双双**解析失败。一度误判为 iOS 智能标点污染。
- **真凶（用户提供 ICS 原文后翻案）**：RFC 5545 要求 TEXT 的逗号转义为 `\,`、分号为 `\;`，
  解析器只还原了 `\n`，**残留的反斜杠让 `JSON.parse` 失败**。
- **定案**：新增 `unescapeIcsText` 单趟反转义（`\\` `\;` `\,` `\n\N`），折行展开兼容 TAB 续行。
  **v1/v2 共用此文件，一次修复两版同愈。**
- 智能标点容错 `normalizeSmartJson` 保留——防的是另一类真实输入（手打 JSON 被键盘替换）。
- **教训**：两个版本同时出错 = 大概率是共用的底层组件，不是迁移 bug。

## 2.4 迁移丢容错（workdays-core 接入时踩的）

- **现象**：把节假日拉取换成 `createHolidayHub` 时，原实现的"拉不到→空数据→周末推演"
  降级被顺手删了——core 一抛错整个请求就崩。
- **定案**：补回 try/catch 降级。
- **教训（重要）：替换一段代码时，它携带的容错语义也是接口的一部分，必须一并迁移。**

## 2.5 最外层兜底网

- 外部输入各自有 try（日历逐条、外部源逐个+5s 超时、env JSON、节假日），
  但**内部逻辑意外没人接**。
- **定案**：主 handler 整体包最外层 try/catch。任何未接住的异常 →
  **HTTP 200 + 格式合法的降级响应**（fields 空 → 手机 Apply\* 空转不误动）。
- **为什么 200 不是 500**：手机端 fetch 拿到 500 会让整条同步失效；
  200 + 空状态让手机"安全地什么都不做"。

## 2.6 core 是外来代码，健康状态要一眼可见

- 抛错/空 → 降级并告警；新增**结构校验**（date 合法 + isOffDay 布尔）剔除脏条目。
- **值错（格式对但判定错）无法自动检测**——那是 core 测试套件的职责，网关信任其事实。

## 2.7 构建阻断：v1-legacy 文件闭包缺失

- **现象**：Cloudflare 构建反复报 `Could not resolve ./v1-legacy.js`。
- **根因**：包内 `src/` 缺 /v1 冻结路径的五个文件。
  **测试未暴露**是因为用例只 import v2 的 router/plugins，从不走 index.js 的 legacy 分支；
  唯有 Cloudflare 构建解析全部 import 才触发。
- **教训**：交付含双轨（冻结+现役）的包，必须做**"从入口全图解析"校验**，
  不能只靠单测（单测可能永不触及冻结路径的 import）。此校验纳入交付纪律。

# §3 架构决策考古（为什么是现在这个样子）

## 3.1 命名规则 + 字段订阅（V11 核心，V12 升格为契约15）

- **动机**："改一处、另一处静默失效"——silent 曾靠 `FOLLOW_FOCUS` 跟随 focus，删 focus 就塌。
- **定案**：规则引擎产出**命名时刻表**；字段用五旋钮订阅（USE/MAP/SKIP/OWN/APPLY）。
  **依赖方向 = 字段→规则**，字段间零引用。
- **V12 升格为契约15（中立规则原则）**：消费者只认规则名，不认生产者，更不认其他消费者。
  删除矩阵已验证：删任一消费者 → 另一方零感知；删 quiet → 双方各自落地为无主张 + audit 大字报。
- **配置腐败判据**：边界时刻相同，**语义同源** → USE 共享（改一处全跟）；
  **数字巧合** → 各自 OWN（互不牵连）。用巧合数字冒充共用是腐败。
  （真实案例：media_volume 曾抄 quiet 的四个边界数字，改为 `USE:"quiet"` + MAP。）

## 3.2 长假夜间重进修正（契约2/4 的由来）

- **现象**：level 合并使长假夜间 22:25 不再是值变化，`on_change` 下"白天手动取消静音 →
  整个假期夜里不再重进"。
- **定案**：长假白天从"不输出"改为**产出 null 释放边界**，时间线变 `on→null→on` 交替
  ——白天无主张（手动自由），夜间 `null→on` 是真变化，夜夜重进。
- **配套（契约4 增补）**：**期望 null → 执行器删除 `last_applied[字段]`**（写哨兵 `none`）。
  否则释放期后的重新主张会被旧缓存误判为"没变"。

## 3.3 config.user 纯增量

原"全量个人配置"333 行与默认层 diff 后真实差异仅 3 处。
**定案**：user 层只写差异（对象深合并、数组整段替换、删行即回落默认）。

## 3.4 外部闹钟：网关只做"具体点搬运工"

**弯路：`RECURRING_ALARMS` 加了又删。** 曾让网关内置"每月9号"式循环规则——**定位错误**：
简单循环 iPhone 时钟 App 自建即可；复杂计算（工作日/间隔/自然月去重/跳节假日）是**乙方业务**。
详见 `EXTERNAL-SOURCES.md` §B9。**未来若有人再想给网关加排期能力，先读那一段。**

## 3.5 Fixed 闹钟：时间的真相在手机

网关对 `GateFix-*` **只开关、从不碰时间**。改响铃时间 = 改手机那条闹钟；
代码里 `scheduledAt` 只是镜像（窗口布防判断 + 显示），**手机改了记得同步镜像，纯为不骗人**。

## 3.6 周末上课：时段化 + 能固定就固定

- **真实矛盾**：同一节课寒暑假与平时时间常不同；而 iOS 固定闹钟**一个 label 只能焊死一个时间**。
  "叫醒级可靠（固定常驻）"与"时间随假期变（动态）"天生打架。
- **解法**：`fixed` 指定**锚时段**。当天时段时间 == 锚时间 → 复用固定；≠ → 自动降级动态。
  逐课、逐时段自动选。
- **踩过并已铲除的坑**：曾用假期**中文名**匹配，但范围名带装饰（`"暑假(每年固定)"`）≠ 键，
  只好加 `includes` 子串回退——**脆弱**。现用英文 `key` 精确匹配。
  **教训：跨模块匹配契约必须用稳定标识，不能用展示名。**

## 3.7 上帝模式的 overlay 不是特权层

god_mode 是一张普通的**事实 schedule**，quiet/wake-alarms/weekend-class 各自 deps 它、
命中日各自**让位**。契约8 的三层叠加由此达成，而**单一 owner（契约6）不破**。

## 3.8 迟到断言窗口：刺客与轮询是互补双轨，非替代

整点轮询使边界断言最晚迟到 1 小时，期间手动操作会被吃掉一次。
**裁决**：边界刺客**长期保留**且写同一份 `last_applied`（准点断言 + 落账），
轮询降级为自愈兜底。

## 3.9 诊断通道：produce 可返回 `{segments, notes}`

god-mode 解析失败原为静默吞错。改为 notes 转 trace ——
**纯度不破**（notes 是返回值不是副作用），诊断可见。

## 3.10 设备抽象：平台差异分三类各归一层

（2026-07-20 设计定稿，待实施）Ivan 指出两处失误：guards 的 app 值直接写 iOS 包名
→ 平台细节漏进契约；为兼容硬加字段级裸 GUARDS → 两个来源不统一。
并明确要求**先设计后编码**（此前有未经同意即改代码的教训，已认错）。
详见 `DEVICE-ABSTRACTION.md`。
