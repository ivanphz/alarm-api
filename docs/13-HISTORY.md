## 2. 规则原子化：为什么推翻五旋钮

**五旋钮**（`USE` / `MAP` / `SKIP` / `OWN` / `APPLY`）是 V12 的字段订阅机制。
它的死因不是难用，而是**表达不了三样东西**：

1. **日型条件** —— 写不出「13:29 仅工作日归零」（`09-KERNEL` §5 自己标注了这条）
2. **边界级差异** —— `apply` 是字段级，想给某一个时刻单独换判据只能整个字段一起换
3. **算出来的时刻** —— 时刻只能是常量，于是出差日闹钟 08:10 才响、状态却 07:44 就解除

### 2.1 三根轴是怎么拆出来的

旧命名 `once` / `enforce` / `on_change` 看着是三个并列的档位，
实际是**两根轴的混合投影**：

| 旧名 | SHAPE | APPLY |
|---|---|---|
| `once` | pulse | always |
| `enforce` | level | always |
| `on_change` | level | if_changed |

拆开之后立刻多出几种以前写不出来的组合（如 `pulse + if_differs`）。

> **「三个并列的名字」往往是没拆开的多维度。** 这个模式值得记住。

### 2.2 日型为什么是四根正交轴，不是一个标签

压成单标签就是 5×2×2×2 = 40 种组合，加一维翻倍 —— 那是组合爆炸不是分类。

而且**分开更准**：出差最后一天傍晚已经到家，`night=home` 但 `morning=work`，
单标签表达不了这种交叉。

### 2.3 全 pulse 是三次修正的结果

1. 最初用 level（持续主张）→ **白天手动开的专注被误关**
2. 改成「有界电平 + 窗口」→ 窗口在常规日子提供不了任何东西，
   却制造出落不到刺客上的撤销边界（[08](08-LESSONS.md) §3.4）
3. 最终全 pulse → 段查询看不见 = 白天绝对安全；同值不合并 = 长假每晚照常进睡眠

代价是漏发补不上 —— 这个交给回传自愈（[10-SELFHEAL](10-SELFHEAL.md)），
而不是靠时间线上的窗口硬撑。

### 2.4 门铃为什么存在

边界全部落在六个刺客上时零门铃。**唯一的例外是算出来的时刻**
（出差日闹钟 08:10 → 解除 08:30），那一刻手机上没有时间自动化，不会醒。

门铃 = Bark `active` 推送 → 通知触发自动化 → 跑 SyncAll。
呈现被勿扰拦掉但触发照跑，所以它能用在清晨而不吵醒人。

## 3. 想过但没做（以及为什么）

| 方案 | 否决理由 |
|---|---|
| 服务器解析 ICS 判断变化 | 它就得懂关键词/区带/日型 → **规则变成两份真相**。只算哈希不解析才对 |
| 心跳「向回追溯 N 分钟内错过的 pulse」 | 服务端分不清「漏了」和「守卫故意拦了」→ 会把被守卫跳过的边界重放，正好请回守卫要防的误伤 |
| 专注变更自动化当触发因 | 系统自己开睡眠也会触发它 → 多跑一次 SyncAll → 撞上单槽忙丢，把别的触发挤掉 |
| 缓冲埋点日志（能省 0.32 秒） | 被杀时缓冲全丢，而那正是**唯一需要日志的场景** |
| 把逻辑下沉到手机（JS 变换动作） | 违背「规则的唯一真相在服务端」 |
| 把 `la` 搬到云端 | 不可观测字段的记忆搬到哪都只知道「我做了什么」，不知道「你之后改了什么」 |
| 窗口终点「吸附到下一个刺客」 | 周末会吸到 12:15 —— 上午的解除和中午没有任何语义关系。**机制迁就实现，不是设计** |
| 服务端加 `silent_state` 解析表 | 拿「呈现」当契约，正是铁则7 禁止的。走手机端隔离带 |

## 3.1 规则表阶段另外否决的（来自原 RULE-TABLE §9）

| 方案 | 否决理由 |
|---|---|
| 字符串表达式 `"workday && block>=3"` | 要写解析器；GUI 无法双向读写；与 guards 的结构化形态不一致 |
| 枚举式日型（把「工作日第二天」当独立日型） | 字段爆炸。一根轴解决整族 |
| 规则优先级 / 后写覆盖 | **静默择一最难查**。改用「冲突即报错 + 把条件写窄」 |
| 内核持有原子名单 | 加插件要改内核 |
| 保留 `quiet` 插件与规则表共存 | 同一决策两个来源，必然漂移。要么全走规则表 |
| DSL 支持函数/循环/自定义算子 | 解释器会长成第二个内核 |
| 靠静态推理判断原子互斥 | **推不出来**。反例：「上班」与「休息」在全天请假日**同时为真** |
| 改排班时修改旧时间段 | 破坏「时间线是纯函数」，历史查询结果会变。只许追加新段 |

## 3.2 两条被走过的弯路

**`RECURRING_ALARMS`（加了又删）** —— 曾让网关内置「每月9号」式循环规则。
定位错误：简单循环 iPhone 时钟 App 自建即可；复杂计算（工作日/间隔/自然月去重/跳节假日）
是**业务侧的事**。网关只做「具体时间点的搬运工」。
> **将来若有人再想给网关加排期能力，先读这一条。**

**周末上课的固定 vs 动态之争** —— 同一节课寒暑假与平时时间常不同，
而 iOS 固定闹钟**一个 label 只能焊死一个时间**。「叫醒级可靠」与「时间随假期变」天生打架。
解法：`fixed` 指定**锚时段**，当天时间 == 锚时间则复用固定闹钟，≠ 则自动降级动态。

## 3.3 几条今天仍然要守的不变量（来自原 HORIZON §8）

无论将来长成什么样（网页配置、多设备、DSL），这六条不许破：

1. **云端无状态**（除 KV 事实）；手机是实况的最终权威
2. **时间线是纯函数** —— 配置来源无论演化成什么（文件/KV/网页），可预览可测不变
3. **消费者只认规则名**，规则不属于任何消费者 —— 可视化/DSL 都不许打破
4. **网关侧零 iPhone 概念** —— 多设备/多用户/网页配置都不改这条
5. 外部输入**嗅探优先、失败响亮报错、绝不猜**
6. **预留只留形状不留功能** —— 每个「到时才做」都是往既定接口填肉，不是重构

## 3.4 一条方法论：大版本迁移必须做「能力对等清点」

V11 → V12 时丢过两处功能（`Set Focus` 吃变量、切专注的清场逻辑），
原因是**只搬了「当前配置用到的那部分」**，没有逐条核对旧版能力文档。

补救办法是做一张对等审计表，逐条列 vN 的能力 → vN+1 的状态 → 备注。
那次清点还顺带发现 v2 有两项**增强**（`last_applied` 防覆盖、守卫从单一 `current_focus`
泛化成任意实况源）—— 不清点就不知道自己多做了什么。

> **纳入纪律：任何大版本迁移前先做能力对等清点。**
> 判据不是「现在的配置还能不能跑」，而是「旧版文档里写过的每一条，新版在哪」。

## 4. 命名法（宪法级，别再改）

- **API / JSON / token 一律 snake_case 全称，禁缩写** —— 历史教训是 `dnd` 这类缩写
  过几个月没人看得懂
- 文件名 kebab-case
- Gate 标签：`GateFix-*` 预建固定 / `GateDyn-*` 动态。
  **单一前缀 = 一扫全清**，加新动态族不用改手机端
- **时间由网关拼进动态 label**，业务侧 uid 永不含时间 ——
  把正确性开关收在网关手里，业务侧选错的可能性为零

## 4.5 「空头支票」：声称支持却没实现的能力

2026-07-17 实案：我声称 focus「多 preset 天然支持」，但 `la_focus` **只存 action** ——
跨 preset 同 action 切换（勿扰 on → 睡眠 on）会被 `on_change` 判「没变」而跳过，
**新 preset 永不生效**。这张空头支票埋了好几轮才被第三方推演戳中。

修法是把签名升成 `preset|action`。而**真正关键的一点当时没人提**：
preset 必须用 **token** 不用显示名 —— 否则换个系统语言签名就变，天天误判。

> **教训**：说「天然支持 X」之前，先找出**验证 X 的那条路径**。
> 找不到就说明是推断，不是支持。

## 5. 三次「差点搞错」的归因

| 现象 | 一开始以为 | 真相 |
|---|---|---|
| 重构后 07:44 都关不掉 | Turn Focus 需要 priming | **变量自我覆盖**（[08](08-LESSONS.md) §1.3） |
| 上帝模式 JSON 在 v1/v2 双双解析失败 | iOS 智能标点污染 | **ICS 的逗号转义没还原**。两版同时错 = 共用底层组件 |
| ApplyFocus 的 OFF 分支「On/Off 不确定」 | 生产 bug | **导出 JSON 不完整**，UI 里是对的 |

**共同点：现象出现的地方 ≠ 根因所在的地方。** 归因前先问「还有什么能解释这个现象」。

### 5.1 一次完整的「断言 → 证伪 → 翻案」

值得记全过程，因为这个模式反复出现：

1. 我断言「iOS 的 `Set Focus` 开启哪个专注是**编辑期选死、不吃变量**」，
   据此设计了「每个 preset 一个分支、开关不对称」的方案
2. Ivan 翻出 **v1 时代的手册**，里面白纸黑字写着 `Turn $ModeText On` —— **吃变量**
3. 整个方案作废，正解反而更简单：一个动作通吃所有 preset，多语言靠云端查表

> **「这个平台做不到 X」这类断言，代价特别高** —— 它不只是错，还会催生一整套绕行设计。
> 说之前先问：**项目历史上有没有人做到过？**

## 6. 两条关于「什么算共用」的判据

### 6.1 配置腐败判据

两个字段的边界时刻相同时：

- **语义同源** → 共用一份定义（改一处全跟）
- **数字巧合** → 各自独立（互不牵连）

**用巧合数字冒充共用是腐败。** 真实案例：`media_volume` 曾抄 quiet 的四个边界数字，
后改为显式订阅。今天的对应物是 `quietShape()` —— 三个字段共用它是因为语义确实同源
（同一批「该安静了」的时刻），不是因为数字碰巧一样。

### 6.2 Fixed 闹钟的时间真相在手机

网关对 `GateFix-*` **只开关、从不碰时间**。改响铃时间 = 改手机上那条闹钟；
代码里的 `scheduledAt` 只是镜像（用于窗口布防判断与显示）。
**手机改了记得同步镜像 —— 纯粹为了不骗人。**

## 8. 手机端版本变更史（v4.1 → v6.0）

> 原本嵌在装配手册开头 90 行，读手册的人不需要它。搬到这里。
> **最重要的三条已升格成 [04-PHONE](04-PHONE.md) §0 的铁则6/7/8。**

按主题归纳（原文按版本号流水，重复较多）：

### 8.1 结构与编排的三次收敛

| 版本 | 干了什么 | 起因 |
|---|---|---|
| v5.0 | **刺客一次网络喂全部模块**（5 次 → 1 次） | 每个 Apply 各拉一次，浪费且慢 |
| v5.3 | **新增 `SyncAll`：编排只有一份** | 「依次跑哪几个模块」被抄了 8 份（3 轮询 + 6 刺客 + ForceResync）。拉取集中了，编排也该集中 |
| v5.5 | **CheckGuards 改收字典**（不收数组） | 避开「洗数组」的未知行为 —— 当时理由是「未实测不敢赌」，v6.0 才知道赌对了 |

### 8.2 铁则的诞生（都是踩坑倒逼的）

| 铁则 | 版本 | 起因 |

### 8.3 ⭐ 一个被引用五个版本的错误断言

「**结构穿过 `Run Shortcut` 边界会被降级成纯文本**」——
v4.1 一次评审提出，此后 v4.2/v4.3/v5.3/v5.4 反复引用，**从未有人验证**。
v5.4 甚至据此加了三处「洗数据」的块。

2026-07-26 实测（三层传导测谎仪）：**证伪**。字典、URL 信封、数组穿边界全都完好。

而真正的坑在别处：`Get Dictionary from Input` **喂数组会静默返回空**
（Count 3 → 0，不报错）。v5.5 改成收字典恰好避开了 —— **但当时的理由是错的**。

> 这条的价值不在结论，在**过程**：一个未验证的断言可以在文档里活五个版本，
> 还催生出三处防御性代码。**引用一条论断之前，先问它是谁测的。**
