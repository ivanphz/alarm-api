# 执行器通道总册 —— CHANNELS（alarm-api/docs/）

> **这份文档是什么**：iPhone 执行层的全部"打断/提醒/触发"能力清单与选型判据。
> 以后任何"我想被提醒/被打断/被触发"的新需求，**先查此表再设计**。
> 全部关键断言均有 2026-07-18 实测支撑（§6），实测优先于任何官方文档与直觉。

---

## 1. 输出通道谱系（按打断力降序）

| # | 通道 | 穿静音 | 穿专注 | 无人值守建 | 无人值守改 | 无人值守删 | 用户状态 | 备注 |
|---|---|---|---|---|---|---|---|---|
| 1 | Fixed 闹钟 `GateFix-*` | ✅ | ✅ | 预建 | 只开/关 | — | 无 | 自定义铃震；常驻最可靠 |
| 2 | 动态闹钟 `GateDyn-*` | ✅ | ✅ | ✅ | ❌（关旧建新） | 需人工确认 | 无 | 默认铃；漏同步=漏响 |
| 3 | Urgent 提醒（26.2） | ✅实测 | ✅实测 | ✅（Add 有 Urgent 参数） | ✅（铃伴生于日期，改期即改铃；Urgent 开关本身不可改） | 需人工确认 | 完成/贪睡 | 真闹钟+完成语义；只在 Find My 主设备；需"闹钟"权限 |
| 4 | Bark critical 推送 | ✅实测 | ✅实测 | ✅（服务端 POST） | — | — | 无 | 完全穿透 focus 与 silent；配 call=1 近似伪闹钟 |
| 5 | Bark timeSensitive | ❌ | ❌实测（DND 下无亮屏无声） | ✅ | — | — | 无 | 呈现被拦**但仍触发自动化** |
| 6 | 提醒 + Alert At Time | ❌ | ❌实测 | ✅ | ✅（同 #3 伴生模型） | 需人工确认 | 完成 | 到期通知；持久躺清单 |
| 7 | 日历 VALARM（订阅册） | ❌ | ❌ | ✅ | ✅（整册刷新） | ✅ | 无 | 受 Event Alerts 总开关 |
| 8 | 普通通知 / Bark active | ❌ | ❌ | ✅ | — | — | 无 | **机器门铃首选**：零打扰仍触发 |
| 9 | 静默层：清单条目（无 Alert）/ badge / 邮件 | — | — | ✅ | ✅ | — | 完成 | "等你"而非"打断你" |

**核心实测事实：通知的"呈现"与"自动化触发"完全解耦。** 触发发生在送达层，
DND/专注/通知摘要只拦呈现、拦不住触发。由此：门铃与人声分离——机器命令用
active（无光无声），给人的紧急事件才用 critical。

**一句话边界**：绝不能漏 + 必须吵醒 → 1；要打断、漏了不致命 → 2/3；计划外紧急 → 4；
要被看见、可勾掉 → 3/6；只是清单一条 → 9；机器叫机器 → 8。

## 2. severity 路由（域声明语义，网关选通道）

| severity | 落点 | 语义 |
|---|---|---|
| `critical` | 动态闹钟（既有 `GateDyn-ES-` 通道） | 必须打断（还款响铃） |
| `high` | todo + **Urgent** | 必须打断 + 要完成语义 |
| `normal` | todo + Alert At Time | 到点提一声，可勾掉 |
| `low` | todo 无 Alert | 静躺清单 |
| （计划外事件·给人） | Bark critical / timeSensitive | 推通道 |
| （机器命令） | Bark active | 零打扰门铃 |

同一业务事件允许同时进闹钟通道与 todo 通道（两套 uid 空间、互不相识）。
**landing**（urgent/alert/silent）是**出生属性**，事后不可改——变更 = 墓碑旧条 + 新建
（见 TODO-CHANNEL.md §10.5）。⚠️ 此字段旧称 `mode`，已按 KERNEL §18 改名（撞 focus preset）。

## 3. 触发面与执行语义（实测）

**触发器执行模型**：单槽、串行、**忙碌即丢弃**——运行期间到达的触发全部丢失，
不排队、不合并补跑（B3/B4）。空闲时约 1.5 秒/班串行消费。
**盲窗**：重启后到首次解锁前，通知照常送达呈现，但自动化动作不落地（E3）。

**可用触发器**：时间、闹钟响/**停止**/贪睡（起床钩子：Any Alarm Is Stopped +
以 Shortcut Input 的 Label 判 `GateFix-` 前缀，勿在选择器绑死对象、勿用 Goes Off）、
睡眠日程、到达/离开地点、充电器连接/断开、电量、CarPlay、蓝牙/WiFi、NFC、App 开/关、
专注开/关、收到通知（App + Title/Message/Subtitle contains 过滤）、
收到邮件（Sender/Recipient/Subject/Account）、收到信息、声音识别。

**预留**：Alipay/微信支付通知触发 → 记账钩子；钱包交易触发。

## 4. 推/拉分工（定时器瘦身，不清零）

- **拉 = 地基（电平语义）**：已知边界时刻 + 低频心跳。计划内时刻本就是网关算的，定时器是正确工具。
- **推 = 快路径（边沿语义，不可靠）**：计划外变更 → Bark active 门铃 → 手机立即拉一轮。
  推丢了最坏退回现状，等心跳。
- **回响推送**：单槽忙丢（§3）意味着一声门铃可能撞在同步进行中而蒸发。
  网关对关键变更（god-mode、请假）**同一门铃双发**，间隔 ≥ 2 分钟（> 单轮同步最坏时长）。
  门铃幂等，多按无害。

## 5. 命令通道纪律

1. **门铃不是信件**：通知内容只做路由（关键词选指令），永不作为指令内容；
   被触发的指令一律带 key 去 GET 网关拿权威状态。泄露 Bark key 最坏 = 骚扰门铃。
2. **推送是快路径不是地基**（§4）。
3. **计划内归定时，计划外归推送**。
4. **完成语义归人**：任何自动化不得把提醒事项置为已完成。
5. **机器门铃用 active 档**：零打扰、照触发；critical 只留给必须叫醒人的事。

## 6. 手机能力实测台账（**唯一真相源**）

> **台账纪律**：每条实测结论必须标注它**约束了哪条契约/铁则**。
> 只记"这个能力是什么样"而不记"所以我们的设计必须怎样"，就是死知识——
> 事实躺在文档里，规则却指着反方向（曾真实发生：DEVLOG §1.4 记了"布尔渲染成 Yes/否"，
> 而 PHONE 铁则1 却写"比较一律先过 Text"，两者矛盾，人跟着铁则走，坑照踩）。
>
> **新发现的手机行为一律先进本表**，再决定它该改契约、改铁则、还是只是备查。
> 详细的"现象→根因→否决了什么"叙事在 `DEVLOG.md` §1；本表是速查与影响索引。

### 6.1 快捷指令引擎行为（跨所有指令，最容易致命）

| 项 | 实测结论 | 约束了什么 |
|---|---|---|
| **布尔渲染** | `Text(true)` **中文系统→「是」，英文→「Yes」**，历史上还出现过 `1`/`0`、`true`/`false`。**呈现随系统语言与版本漂移，不是契约** | ⭐ **契约: 信封零裸布尔**，真值一律 `"true"`/`"false"` 字符串（有全量扫描测试守着）· **PHONE 铁则7**：iOS 自产布尔须建语言无关隔离带 |
| **判空** | `has any value` 存在"数字 0 即空"的版本怪癖，两端行为不一致 | **PHONE 铁则1②**：判空一律标记法 `Text: X(变量)` → `If is X` |
| ~~**类型强转（双向）**~~ **已证伪**（实测 2026-07-26） | 穿两道 `Run Shortcut` 边界后：手工字典 ✅ / `Get Contents of URL` 信封 ✅（读出 `version:2`）/ 数组 ✅（Count=3）—— **洗与不洗都完好**。原断言"结构跨边界极易被降级成纯文本"自 v4.1 被引用五个版本，**从未验证，现已证伪**。<br>仍未覆盖：三层以上链路、其它 iOS 版本 | 洗数据**不是**为了防这个（它不存在）。留着只是 1 块的保险，且**只对字典安全** |
| ⛔ **`Get Dictionary from Input` 喂数组 = 静默清空**（**实测** 2026-07-26） | 数组 `[1,2,3]` 穿两道 `Run Shortcut` 边界后：**不洗 Count = 3（完好）**；**洗过 Count = 0（清空）**。**不报错、不提示** | ⭐ **PHONE 铁则8**：判据是"它是不是**字典**"，不是"它是不是结构"。<br>⛔ 绝不对数组洗；✅ 要传数组就**包进字典再传**，接收方洗字典、内部掏数组 |
| ~~**级联放大**~~ **前提已证伪，仅存档** | 原推论：一处没洗 → 直通失效 → 每个下游模块各自重发网络（1 次变 5 次）。该推论建立在"跨边界会降级"之上，**前提已证伪，故大概率不成立** | 保留仅为记录推理链；**不要据此加防护** |
| **变量覆盖** | `Get Value … → Set 同名变量` 把字典覆盖成字符串，后续取值全空 | **PHONE 铁则4**：不用不同类型覆盖同名变量（布尔标志位 0/1 累加是例外） |
| **contains** | 是**子串**匹配非成员匹配：「工作」⊂「工作模式」，`com.app.a` ⊂ `com.app.about` | **PHONE 铁则5**：两边补分隔符 `\|A\|B\|` contains `\|A\|` · **契约**: 守卫 `match[]` 由服务端展开，手机逐项精确相等 |
| **JSON 导出** | 导出不完整（如 Set Focus 的 On/Off 标志不被序列化），与 UI 实际不符 | **PHONE 是文字真相源**，审指令以 UI 显示为准，不信导出 |
| **文件扩展名决定解析** | 文件名 `.json` → UTI `public.json` → `Get Text from File` **先按 JSON 解析**；内容若非合法 JSON（如裸 token `on`）**静默返回空**，写入却完全正常。旁证：文件缩略图空白 | ⭐ **PHONE §10**：`last_applied` 一律 `.txt`。**存什么格式就用什么扩展名**，别拿 `.json` 当"配置文件"的泛称 |
| **后台预算** | 锁屏后台约 40~80 秒非确定被掐，**掐尾部** | 关键动作不置尾；对账靠幂等，掐哪算哪下轮补齐 |
| **后台调试** | `Show Alert` 后台不一定弹；**前台正常 ≠ 后台正常** | 用 `Append to Note` 探针（非文本变量须先过 `Text`，否则存成 `Attachment.txt`） |
| **自动化触发** | 「运行前询问」不关则后台完全不触发 | 上线冒烟必查项 |

### 6.2 专注 / 音量 / 设备状态

| 项 | 实测结论 | 约束了什么 |
|---|---|---|
| **Turn Focus** | **本身即生效，不需要 priming 前置**（旧结论"必须先 Get Current Focus"是误归因，真因是变量自我覆盖） | DEVLOG §1.1 已更正 |
| **Set Focus 吃变量** | 吃**本机语言显示名**的文本变量（`Turn $NameText On`）；喂 token 无效 | **契约**: 下发 `resolve.current_focus[preset]` = 本机名**候选数组**，手机逐个试开验证 |
| **候选名数组** | 数组过 `Text` 会变成 `"A, B"` 死文本，喂 Set Focus 必失效 | **PHONE §7 F23**：绝不加 Text |
| **Set Focus 异步** | 是**异步系统总线事件**，开启后立刻 `Get Current Focus` 会读到**旧**专注名 | ⭐ **PHONE §7 F35a**：开启后 `Wait 1 Second` 再验证（1 秒起步，偶发失败提到 2 秒） |
| **单专注限制** | 同时只允许一个 Focus，切换须先 Turn 当前 Off + Wait 1s | **PHONE §7 F30-F31**；且**当前已是目标候选之一时跳过清场**（否则绑该专注的其他自动化被误触发两次） |
| **自定义专注** | 用户**自建**的专注，名称**不随系统语言变** | 零维护逃生门：自建一个替代内置勿扰，表里一行固定名，换语言零影响 |
| **Device Is Locked** | 返回 iOS **原生布尔** | **PHONE 铁则7 / §3 G17**：必须 If 布尔 → 写死文本 `true`/`false`，否则与 `resolve.locked` 对不上 → fail-closed 100% 拦截 |
| **音量** | 手机侧读数 0–1 浮点 | **契约**: `media_volume` 下发整数 0–100，执行器 ÷100 |

### 6.3 闹钟（★ 与提醒事项模型根本不同）

| 项 | 实测结论 | 约束了什么 |
|---|---|---|
| **只有四个操作** | **建 / 开 / 关 / 删。没有"改"** ——快捷指令无"修改现有闹钟时间"的动作 | ⭐ **PHONE 铁则6** + **契约 KERNEL §12**：时间必须编进标签，改时间 = 关旧建新 |
| **Create Alarm** | 建出来的闹钟**铃声/震动只能系统默认**，指定不了 | 需自定义铃震或**绝不能漏响**（叫醒）→ 预建 `GateFix-`；否则动态 `GateDyn-` |
| **Find Alarms** | 按 **`Label`** 筛（不是"名称"）；支持 `is` / `contains`；**支持 `Is Enabled` / `Not Is Enabled` 筛选** | **PHONE §8 A22** sweep 加 `Is Enabled` 只扫开着的；**§9 C3** 用 `Not Is Enabled` 直接筛出待删 |
| **删除** | 动作叫 **`Delete`**，**需人工确认**；逐条 `Delete Repeat Item` 每条弹一次，**整列表一次传入只弹一次** | **PHONE §8**：无人值守只关不删；**§9** 人工清扫仪式整列表传入 |
| **起床钩子** | `When Any Alarm Is Stopped` 用 **Shortcut Input 的 Label** 前缀分流（**别用 Goes Off**——那是响起未醒；**别在选择器绑死具体闹钟**） | PHONE §11C |

### 6.4 提醒事项 / 推送 / 触发（2026-07-18，iOS 26.x）

| 项 | 实测结论 | 约束了什么 |
|---|---|---|
| 删除类动作 | Remove Reminders 需人工确认，无法静默删除 | TODO-CHANNEL：无人值守只建只改，删除走人工清扫 |
| Set Detail | 可无人值守改 Title/Notes/Due Date/Priority/Is Completed/Is Flagged/List/Tags/URL；**无 Urgent 项** | landing 变更须墓碑+新建（Urgent 是出生属性） |
| 铃的伴生模型 | 铃随 Due Date 走：**改期即改铃**（R4）；向 Due Date 喂任意非日期文本即清空日期、铃随之消灭；移列表不消铃（E2） | ★ **与闹钟相反**（闹钟不能改）：todo 是"改期即改铃、身份不变"，**两者对账模型不可互相借鉴** |
| Add Reminder | 有 Urgent 开关与 Alert At Time；Urgent 实响穿透 DND（R2） | severity→landing 映射 |
| Find Reminders | URL contains 命中自定义 scheme（V1）；无 List 过滤即全库跨列表（R5）；Due Date 运算符含 is after / **is in the next**（R1）；有 Completion Date、Has (No) Alarms 过滤 | 墓碑查询用 `is in the next N 天` 天然排除过期条目 |
| Bark 三档 | active/timeSensitive 在 DND 下呈现被拦、critical 完全穿透；**三档均触发自动化**（B1） | 机器门铃一律 `active`：零打扰、照触发 |
| 触发语义 | 通知 15/15 到达、执行 9/15：单槽串行忙丢；长任务运行期触发 30 响仅首响生效，无排队无补跑（B3/B4） | 门铃不可靠 → 关键变更回响双发；心跳地基永不撤 |
| 执行预算 | 锁屏后台 40~80 秒非确定被掐，掐尾部；网络往返 ~1.3s/次，本地操作 ~0.2s/次（E1） | 单轮目标 <30 秒；网络调用尽量少 |
| 盲窗 | 重启后首次解锁前：通知送达正常，**自动化动作不落地**（E3） | 解锁后首次心跳幂等补齐，不做特殊处理 |
| 通知摘要 | 由呈现/触发解耦推论：不影响门铃（B2 推论关闭） | — |
