# 01-CONCEPTS — 读懂这个项目

> 只讲**现在生效**的概念。历史上的机制（五旋钮、quiet 插件、once/enforce 三档命名）
> 已退役，要考古去 git history。

---

## 1. 一条规则原子 = (触发因, 条件, 效果)

```
触发因: clock@20:55        什么把这条规则叫醒
条件:   { night:["home"], eve:["workday"] }    今天算不算数
效果:   focus = sleep|on, pulse, if_changed, 守卫 none    算数就做什么
```

三者独立可换。这就是「规则原子化」的全部含义。

---

## 2. 边界（boundary）

**一个边界 = 某一刻，某个字段该变成什么。** 时间线就是边界的有序集合。

```
07:44  focus = sleep|off      ← 一个边界
20:55  focus = sleep|on       ← 又一个
```

边界的时刻可以是**字面量**（`"20:55"`），也可以是**算出来的**：

```js
at: { from:"wake_alarms", pick:"last_wake", offset:20,
      not_before:"07:44", fallback:"07:44" }
```

「当天最晚起床闹钟 + 20 分钟，但不早于 07:44，算不出就用 07:44」。
所以出差日闹钟 08:10 → 解除 08:30，而平时闹钟 06:29 → 吸附到 07:44。

---

## 3. 三根正交的轴

一个边界的「效果」由三样东西描述，**互不相干**：

### 3.1 SHAPE 主张形状

| | `level` 电平 | `pulse` 脉冲 |
|---|---|---|
| 语义 | 从此刻起**持续主张**到下一个 level 边界 | **一次性事件**，之后不主张 |
| 相邻同值 | 合并（视为没变化） | **不合并**（今晚的 on 不是昨晚那个 on） |
| 段查询看得见吗 | 看得见 | **看不见** |
| 可选 `until` | 有界电平：到点自动撤销主张 | 无（时长本来就是 0） |

**目前 focus / silent / media_volume 的边界全部是 pulse。** 为什么：

- 段查询看不见 → **白天你手动开的专注绝不会被误关**
- 同值不合并 → **长假连着几晚照常进睡眠**（level 会被合并成只剩第一晚）

代价：某次没跑成（手机没网）就补不上了 —— 这交给**回传自愈**，不是靠时间线硬撑。

### 3.2 APPLY 执行判据

叫醒之后，凭什么决定动手：

| 值 | 判据 | 信封里下发为 |
|---|---|---|
| `always` | 收到就做（守卫仍可否决） | `enforce` |
| `if_changed` | 与手机本地记忆 `la` 比，变了才做 | `on_change` |
| `if_differs` | 与**实测态**比，不一致才做 | 未实现，等自愈 |

> `la`（last applied）不是缓存优化，是**策略**。它区分了观测分不出的两件事：
> 「你半夜手动关掉的」（期望=la → 不重开）vs「我压根没开成」（期望≠la → 补开）。

### 3.3 守卫 guard

前置否决，**优先级高于一切，包括强制推平**。

```js
guard: "none"     // 当前没有任何专注才动手 —— 手动开着就让路
guard: "sleep"    // 只解除睡眠，别人的现场不碰
guard: ["none", "sleep"]   // 多值
```

守卫判 SKIP → 不动手、**不落账**（`la` 保持原值，这本身承载信息）。

#### 3.3.1 两个作用域

| | 例子 | 写在哪 |
|---|---|---|
| **恒常型** | 「调音量永远躲开导航/视频/音乐」—— 字段的固有不变量，与时刻无关 | 字段级 `GUARDS_ALWAYS` |
| **时点型** | 「07:44 关睡眠，但仅当此刻确实是睡眠」—— 只在那个边界成立 | 规则的 `guard` |

**二者可叠加**：「12:15 归零音量，但开着导航就别归」= 时点守卫 AND 字段恒常守卫。
下发时合并成**一个数组**，手机端只见一套，不知道有两个来源。

#### 3.3.2 `source` 词表（开放枚举）

守卫的本质是「执行前检查某个手机实况」，`current_focus` 只是其中一种：

| source | 手机怎么取 | 值 | 用途 |
|---|---|---|---|
| `current_focus` | Get Current Focus | token | 保护手动开的专注 ✅ 在用 |
| `app` | Get Current App → bundle id | bundle id | 开着导航就别归零音量 ✅ 在用 |
| `locked` | Get Device Details → Device Is Locked | `"true"/"false"` | 锁屏/解锁态 ✅ 在用 |
| `charging` | Get Device Details → Is Charging | `"true"/"false"` | 预留 |
| `wifi` | Get Network Details → SSID | 文本 | 预留（在家/在公司） |
| `battery` | Get Device Details → Battery Level | 数字 | 预留（低电量降级） |

**加一个 source = 手机端 CheckGuards 多一个取值分支**，服务端零改动 ——
守卫的比对逻辑是通用的，不认识具体 source 也能跑。

`op`：`is` / `is_not`（单值）、`in` / `not_in`（集合，value 必须是数组）。
**否决 `contains` 做集合判断** —— bundle id 前缀高度重合（`com.app.a` ⊂ `com.app.about`），
子串匹配会误命中。

## 4. 日型 — 四根正交的轴

「今天算不算数」的判据。**不是一个标签，是四根轴**——压成单标签就是
5×2×2×2 = 40 种组合，加一维翻倍，那是组合爆炸不是分类。

| 轴 | 取值 | 含义 |
|---|---|---|
| `morning` | `work` / `leave_short` / `leave_long_tail` / `rest_short` / `rest_long` | 晨间属于哪一类 |
| `noon` | `work` / `off` | 中午在不在上班（决定有没有午休两键） |
| `eve` | `workday` / `rest` | **明天**上不上班（决定在家时几点进安静） |
| `night` | `home` / `away` | **今晚**人在不在家（出差在外 → 晚点再进） |

规则用 `when` 断言这些轴，**取交集**：

```js
when: { night: ["home"], eve: ["workday"] }   // 在家 且 明天上班
```

一格可以有多条变体（数组），但 **when 必须互斥** —— 同时命中两条 = 编译期报错。

产出在 `plugins/day-type.js`，可从 `/v2/timeline?debug=1` 的 `schedules.day_type` 看到。

### 4.1 ⚠️ 一个还没改的命名陷阱

`presence` / `restdays` 产出的两个字段**名字看着互斥，实际不是**：

```
workday: 按法定/调休，今天该不该上班
rest:    今天实际在不在休息（法定休 或 全天请假）
```

**全天请假那天 `workday=true` 且 `rest=true`。** 照字面理解写规则必然出错。

原设计稿建议改名为 `work_scheduled` / `resting`（并加 `⚠️ 二者不互斥` 的标注），
但**至今未改** —— `plugins/day-type.js` 里用的还是 `p.workday` / `p.rest`。
写新规则碰到这两个字段时格外小心，或者顺手把改名做了。

> 更一般的教训：**不能靠静态推理判断两个条件是否互斥**。引擎无从知道
> 哪些组合不可能，所以规则冲突只能靠运行时报错 + 空匹配探测（[02-RULES](02-RULES.md) §6.1）。

## 5. 触发因 — 谁把手机叫醒

**这是最容易想错的一点：触发因不是查表的键，是「这次能看见哪些边界」的过滤器。**

| 触发因 | 手机侧 | 能看见 |
|---|---|---|
| `clock@HH:MM` | 时间自动化（**刺客**）×6 | 该时刻附近的边界，**含 pulse** |
| `doorbell` | 收到通知（Bark `active`） | 同上 —— 服务端唯一能主动发起的入口 |
| `heartbeat` | 低频兜底（未启用） | **只看 level，看不见 pulse** |

### 5.1 刺客白名单

```
20:55  22:25  07:44  09:30  12:15  13:29
```

**边界落在白名单上 = 手机自己会醒 = 零门铃。**
落在白名单外（如出差算出来的 08:30）= 必须靠门铃投递。

### 5.2 门铃是什么

```
Worker cron 发现「08:30 有边界，但白名单里没有 08:30」
  → 推一条 Bark active 通知（呈现被勿扰拦掉，但触发照跑）
  → 手机「收到通知 → 标题含 |SYNCALL|」自动化触发
  → 跑 SyncAll → GET 网关 → 拿到那条指令 → 执行
```

**门铃不是信件**：通知内容只做**路由**（选哪条指令），永不作为指令内容。
被触发的指令一律带 key 去 GET 拿权威状态。

## 6. 采样的两种模式

| | `mode=point`（刺客/门铃用） | `mode=segment`（默认） |
|---|---|---|
| 问题 | 「**此刻**有没有指令要执行」 | 「**现在**应该是什么状态」 |
| 看得见 | 该时刻 ±3 分钟内的边界，含 pulse | 只有 level 的当前主张 |
| 无匹配时 | 字段**缺席** = 什么都不做 | 字段缺席 = 无主张 |

全 pulse 之后，segment 查询看不见 focus/silent —— **这是正确行为，不是 bug。**

## 7. 字段与通道

| 字段 | 读得回来？ | 通道 |
|---|---|---|
| `focus` | ✅ `Get Current Focus` | preset token（sleep / do_not_disturb…） |
| `silent` | ✅ `Is Silent Mode On`（Actions app） | — |
| `media_volume` | ✅ | `channel: "media"`（token，不是写死的枚举） |

**通道是 token**，本机名走 `resolve` 表按语言下发。所以加「铃声音量」只是复制字段、
把 `CHANNEL` 改成 `"ringtone"`。

### 7.2 专注名的三重保险

`Set Focus` 必须喂**本机语言的显示名**，而译名可能随 iOS 更新变。三层防线：

| 层 | 做法 | 防什么 |
|---|---|---|
| **1 传参准** | 手机自报系统语言（`?locales=`）→ 服务端下发对应语言的表 | 日常主路径。**不猜** —— 系统什么语言就要什么表 |
| **2 云端可热改** | 表在服务端（`edge/resolve.js`），iOS 改译名 → 加一行，**手机零改** | 译名变更 |
| **3 穷举兜底** | 每个 token 下发**候选名数组**，手机逐个试开 + `Get Current Focus` 验证，成功即止 | 前两层都没覆盖到的空窗；即使传参丢了（降级全语言表）也能撞对 |

> 想彻底摆脱这套：在 iOS 里**自建**一个自定义专注（名字不随系统语言变），
> 服务端表里给它一行固定名，从此零维护。

**可观测性不是旋钮，是约束**：读不回来的字段不能用 `if_differs`。

## 7.1 两类闹钟：可靠性模型

**这是全系统最容易踩错的一条。** iOS 两个硬约束逼出了两类闹钟：

- `Create Alarm` 建的闹钟，**震动/铃声只能用系统默认**，指定不了
- **没有「改现有闹钟时间」的动作** —— 只能建/开/关/删

| | `GateFix-*` 预建固定 | `GateDyn-*` 动态 |
|---|---|---|
| 谁建 | 你在手机上**手工预建**，配好震动/铃声 | 网关按清单随建随删 |
| 网关做什么 | **只开/关，从不碰时间** | 下发具体时间点，手机建/关对账 |
| 响几点由谁定 | **手机**（代码里 `scheduledAt` 只是镜像） | **网关**（时间编进 label，改时间 = 关旧建新） |
| 自定义铃声 | ✅ | ❌ 只能默认 |
| **可靠性** | **常驻**：24h 内任一次同步成功设为 ON 即会响 | **最近一次**同步必须成功，否则当次漏响 |
| **失败方向** | 多响（闹了总比没闹强） | **漏响** |

**判据一句话：需要自定义震动/铃声，或「绝不能漏响」→ Fixed；否则动态。**

- 每天**第一个把你从睡着叫醒的**闹钟 → 必须 Fixed
- 时间会变（上课随寒暑假）、漏了不致命 → 动态

> ⚠️ **不要用时间容差去「纠正」闹钟时间**。Fixed 的时间在手机（网关不下发时间去比）；
> 动态的时间不一致时**本就该重建**。容差匹配会把「该重建」误判成「将就用旧的」，
> 绕回时间不更新的老 bug。**稳定靠 Fixed 常驻，精准靠动态重建，各取所需。**

## 8. 术语速查

| 词 | 意思 |
|---|---|
| **刺客** | 手机上的时间自动化，到点叫醒手机跑 SyncAll |
| **门铃** | Bark 推送，让手机在非刺客时刻醒来 |
| **信封** | 服务端返回的 JSON，手机端读它执行 |
| **la** | last applied，手机本地记的「上次成功交代了什么」 |
| **主张** | 某字段在某时刻「应该是什么」；无主张 = 归你手动管 |
| **释放主张** | 值为 `null` 的边界，意为「我不管了」 |
| **上帝模式** | 日历里写 JSON 直接接管当天，绕过所有规则 |
